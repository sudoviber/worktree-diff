## 执行中的判断记录
- T1：提示行位置：`e.props.scroll` 只给 `bodyRows` 和 `offset`，不给内容总行数，且 terminal 上引擎自己的滚动（把焦点元素保持在视野内、贴底、夹紧）不会重新调 render，`offset` 会过期；按 offset 在顶部/底部之间切换还会因提示行本身挪动内容而来回跳。所以只用 `bodyRows`：render 时粗估整棵树的行数（换行按宽度往多里算，diff 按行数加 margin），估计连同提示行放得下 `bodyRows` 就放在内容最后（marginTop 1），放不下就放在控制行（refresh/list/fold/collapse）正下方、tab 行上方（控制行的 marginBottom 移到提示行下面）。低估时提示行会在底部被滚出视野。（T2 修正：实测估算与测试 painter 逐行相等、并不偏大，所以判断时另留 `KEYS_SPARE_ROWS = 2` 行余量，并加测试锁住「bodyRows 比实际行数少 1 或多 1 时提示行都不在最后」。）
- T1：热键按钮只在 `isFocused` 时画。d.ts 写明 Pane 的 `isFocused` 是 render props，props 变化会重新求值（RenderViewport 注释「a hook reads it as of the last width or props change」），热键只认已画出的 Button；但没有文档保证重绘一定先于第一下按键到达，拿到焦点后极短时间内按下的 j/k 可能落空（pane 持有键盘，不会进输入框）。按 spec 保留「只在聚焦时画」，没有为此常驻画热键按钮。
- T1：`claude plugin test` 的 kit 没有实现 mod 自己的 `$.ui.focus` / `$.ui.scroll`（调用直接抛 `HooksError: no implementation for ui.focus`，不经过测试的 hook），测试里没法观察移动。因此把按键决策拆成纯函数 `navAction(rows, focused, key, isOpen)`（导出，测试用 pane 实际画出的行顺序和缩进深度喂它），`focusRow($, key)` 导出后用假 `$` 测 deny / 抛错 / scroll 失败都不抛；h/l 的折叠、展开、加载 diff 和 q 关闭仍走 kit 的真实按键。kit 里这条「抛错」路径正好覆盖了「$.ui.focus 失败时按键不报错」。
- T1：测试自己触发的 `ui.focus` 事件需要底下有人应答，`world()` 加了 `on('ui.focus', () => ({}))`。kit 里事件形状就是传入的参数，所以观察 hook 的 matcher 只用 `{ requestId }`，不加 `component`。
- T1：点击 `j: down` 这类按键按钮时引擎可能先把焦点环移到按钮上（ui.focus 落在 `nav:*`），观察 hook 忽略 `nav:*`，保留原来的行，否则 j 会永远从第一行开始。焦点记录分两份：`focusedKey`（当前元素，控制按钮也算，j/k 据此判断「不在任何行上」）和 `lastRowKey`（最后停过的行，只用于 autoFocus 落点），所以焦点移到 refresh 等按钮后，下次进入仍落回上次的行。
- T1：`/wt-diff` 不再切换开关：开着且显示时也重新 `open({ focus: true })`；undrawn 的 pane 也带 `focus`（之前只在 isPlaced 时带）。`/wt-diff close` 在 pane 没开时回 `Changes pane is not open.`，多余参数回 USAGE。`l` 在已展开的文件上不动（文件没有子项）；list 视图所有行深度为 0，`h` 不动。
- T2：j/k 连按：按键按钮的 onPress 只把 `pressNav` 丢到后台，第二下可能在第一下的 `$.ui.focus` 往返完成前读到同一个 `focusedKey`。改为模块级 `navChain` 串行执行（导出 `inTurn`）；kit 里 mod 和测试 import 的模块不是同一个实例（测试 import 的 `drawnRows` 为空），所以测试用替身闭包验证串行与失败后继续，而不是走真实的 j。
- T2：`/wt-diff` 在 snapshot 还为 null 时打开的 pane 只画 `Reading git…`，autoFocus 只在拿到键盘那一刻生效，焦点环会落空。`focusPane` 记下 snapshot 是否为 null；是且 pane 已拿到键盘时，等这次 refresh 完成后再查 `isFocused`，按 autoFocus 同样的规则（上次的行，否则第一行）算出目标并 `focusRow`（`$.ui.focus` 会等该元素被画出，有上限）。期间若有行焦点移动（`rowMoves` 计数变了）就不动。kit 没有 mod 侧 `$.ui.focus`，这条没法在测试里观察，未加测试。
- T2：`open({ focus: true })` 只是请求，可能被拒。`focusPane` 在 open 之后读 `$.ui.panes()` 的 `isFocused`，没拿到键盘时回 `Changes pane opened — ctrl+x tab to focus`；假定 open resolve 时 panes 里的 `isFocused` 已反映这次授予（d.ts 没写明时序）。测试 world 的 `ui.open` 按 `grantsFocus` 决定 `isFocused`。
- T2：d.ts 写明 hotkey 按小写匹配（Shift+w 即 `w`），所以 `G` 会触发 `g: top`；README 与 spec 改为如实说明，行为不变。
- T3：按键读的行改为按键当时从 state 现算（`listingNow`：snapshot/view/collapsed → `listedRows` → `navRow`，与 render 同一函数），删掉只在 render 里更新的 `drawnRows`，连按 `lj` / `ll` / `hj` 及热重载后首次重绘前都不再用旧行；`l` 打开文件时只在 chain 里等 expandedAtom 写入（拆出 `flipFile` / `loadDiff`），读 git diff 丢到后台，后续 j/k 不再被慢 diff 堵住；`g` 在 focus 后先 `$.ui.scroll({ to: 'start' })` 再按 nearest 滚到首行（头部比窗口高时首行仍可见），README 改为如实说明顶部提示行会随列表滚走、按 g 回来。kit 仍观察不到 mod 侧焦点移动，「按当时的行」只能用 h/l 的折叠与打开验证。
- T4：收尾检查 validate / test（237 pass）/ tsc 全部通过，docs 与 README 无本地路径；按排除规则同步到 dev-mods 后再跑 validate / test 通过；未 commit。无新增偏离。
